## 坐标与维护

`CAMPUS_PLAN_V2` 为 1280 × 1920 的相对图纸坐标，X 向右、Y 向下，不是经纬度或米。接口使用 `campusPosition: [x, y]`；数据库沿用 `campus_x/campus_z` 字段名称。窗口局部坐标独立，仍属于演示布局。

- `src/data/campus-layout.json` 保存分层轮廓。
- `src/data/campus.ts` 保存交互点中心、朝向、尺寸、配色、源文件名及普通设施名称。
- `src/components/CampusMap.tsx` 实现拖动、滚轮/双指缩放、键盘操作、分级名称和点击入口。
- `scripts/trace-campus.py` 从规范化为 1280 × 1920 的 24 位 BMP 提取底图；仅使用 Python 标准库。

建筑轮廓额外做直线拟合、去除像素台阶和印刷文字产生的小孔，保留主要转角与朝向。树木和等高线状纹理为景观风格表达，不代表实测树位或高程。原始参考图不随前端发布。

地点名称始终可显示，普通建筑名称随放大逐级出现；右下角可隐藏名称。后续精细建筑群模型仍通过稳定场所 ID 绑定，无需重编窗口归属。

## 旧版本兼容

旧 `CAMPUS_SCHEMATIC_V1` 示例坐标不能直接套用新底图。新种子使用 V2，API 返回保存的坐标版本，前端拒绝混用。Pages 目录随代码自动更新。

若曾手动部署旧种子数据库，应先备份，再按稳定 ID 更新七个 venue 的名称、campus_x/campus_z、footprint 和 coordinate_system，不要清空真实业务数据库。当前尚未接入线上数据库。

按当前要求无需地图 Key、在线瓦片或地理配准。只有未来明确增加 GPS 导航时才另行设计地理坐标转换。
