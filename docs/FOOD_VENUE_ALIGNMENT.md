## 保存与使用

- 项目数据：`public/osm/food-venues.geojson`。
- 用户导出：`E:\Acntenn\Map\补充餐饮地点_已审核.geojson`，与项目数据逐字节一致。
- 对齐参照原几何：`public/osm/venue-references.geojson`。
- 完整对齐报告：`public/osm/venue-alignment-report.json`。
- 配准输入：`data/osm/venue-alignment.json`，记录截图文件名、SHA-256、尺寸、蓝色标记像素、控制点、审核状态及室内备注。原截图仍保存在用户的 Map 文件夹，没有复制到公开资源目录。

三个地点均为 GeoJSON `Point`，使用独立 `venue/*` ID，通过 `venue_id` 对应现有业务场所。没有修改 OSM 原始数据、基础图层统计或原图纸坐标。`review_status=approved` 表示用户认可当前定位；`surveyed=false` 表示未进行实地测量。逸夫楼记录 `indoor=true`、`location_note=位于室内`；其他地点不擅自补写室内外属性。

预览入口为 `?basemap=osm`，左侧可点击三个地点跳转局部，并下载 GeoJSON。也支持 `?basemap=osm&venue=v-yifu`、`venue=v-hut`、`venue=v-south` 直接定位。蓝色 × 是餐饮地点，橙色轮廓是对齐参照，虚线圈为 5 米目视检查范围；预览明确标注逸夫楼售卖点“室内”。默认校园底图现已使用这份已审核 GeoJSON，保持三个坐标不变；接入说明见 [GEO_BASEMAP.md](GEO_BASEMAP.md)。

## 复现

```powershell
npm run osm:align
# 可选：核验本机原始截图没有变化
npm run osm:align -- --images-dir '..\Map'
```

脚本仅需 Python 3 标准库，按已保存的截图控制点与 OSM 对应顶点进行局部米制仿射拟合。逸夫楼使用 6 个控制点，四五六餐厅使用 12 个，南门步道使用 4 个。控制点 RMS 残差约 0.100、0.102、0.045 米；这仅说明截图对齐的内部吻合，不能作为实地精度。GeoJSON 的小数位用于复现，不能据此声称厘米级定位。

若将来更新 OSM 快照或定位截图，应先重新审查对齐。测试锁定当前已审核坐标，防止静默漂移。重新生成项目数据不会自动覆盖 Map 文件夹中的人工导出副本。
