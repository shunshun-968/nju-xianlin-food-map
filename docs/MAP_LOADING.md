# 底图分批加载与预取缓存

拖动、缩放和顶部导航动画的性能定位及后续优化见 [MAP_PERFORMANCE.md](MAP_PERFORMANCE.md)。本文记录网络加载和持久缓存策略。

底图视觉、地理位置、食堂入口和室内模型保持原样。运行时不再请求约 3.01 MB 的完整 `campus-render.json`，改为读取 `public/osm/runtime/index.json` 及内容哈希命名的静态分块。无需增加服务器或地图服务。

## 加载顺序

1. 先读取约 14 KB 的目录与约 551 KB 的校园核心包，显示校园及七个餐饮地点。
2. 根据实际屏幕尺寸和原有初始镜头，优先加载初始视野周边；边缘预留 80 米，核心校园始终包含在优先范围内。网络请求最多同时两个。初始范围之外的几何通过 SVG 裁切隐藏。
3. 优先区域加载完成后，等待 450 毫秒，再利用浏览器空闲时间逐块预取其余数据。后台一次只处理一块，低网络优先级；拖动、缩放尚未结束或页面不可见时暂停发起后续请求。已经在途的请求允许完成。
4. 后台只下载、解析和缓存，不挂载外围 SVG 图层。首次缩小到初始倍率以下时，解锁更远范围；当前视窗加 100 米余量内的分块才参与渲染。此后拖动可继续浏览外围，实际路径仍按视窗筛选。

如果用户在预取完成前就缩小，当前视野的需求优先于尚未开始的后台任务；已经请求的同一分块共享 Promise。网络非常慢时仍可能等待尚未下载的数据，但不会重复下载已有数据。外围失败时保留已成功显示的校园，并提供局部重试按钮；重试不会重置镜头。

## 缓存与更新

- 内存保留解析结果和在途请求，从食堂返回校园直接复用。
- Cache Storage 按目录版本保存分块；刷新时先检查最新目录，内容未变则直接读取本地缓存。另有浏览器 HTTP 缓存作为补充。
- 每个文件名含内容 SHA-256 前 16 位，数据变化会产生新地址，不会误用旧版本。目录使用 `cache: no-cache` 重新验证。
- 只清理本应用的旧底图缓存，保留当前和最近一个旧版本。浏览器禁用存储、空间不足或缓存损坏时自动回到网络读取，不阻止地图显示。
- 林地纹理仅在达到显示倍率时单独加载，使用同一缓存机制。

缓存不是离线应用保证：首次启动仍需取得目录，浏览器也可能回收磁盘缓存。

## 数据重建

`campus-render.json` 和原始 GeoJSON 继续作为完整数据来源保留。每个要素只归属一个分块，跨格要素保留完整路径，分块包络扩大至覆盖它，避免道路被切断或重复下载。渲染顺序由原始序号恢复。SVG 路径保持原字串；运行时要素的数值元数据保留六位小数，原始 GeoJSON、场所坐标和地图元数据不改动。

```powershell
# 修改校园或林地数据后，在开发服务器验证前执行
npm run osm:build-runtime
npm test
npm run build
```

正式构建会自动重建目录和分块，仅需 Node.js。生成的运行时文件随仓库提交，保证开发与测试使用同一版数据。构建器不自动删除历史哈希文件；更新发布时先确保新分块可用，再发布新目录。部署清理历史文件时应考虑仍打开旧页面的客户端，避免过早删除旧版本。

## 本次验证（2026-10-22）

- 4,538 个渲染要素完整恢复、无重复，路径及原始绘制顺序一致；核心包含 1,104 个要素，外围分为 39 块。
- 2048×1112 桌面视窗冷启动：优先分块共约 2.08 MB（包括核心包，不含目录与应用 JS/CSS）；其余 15 个分块在优先区域就绪后预取。
- 预取前后初始视野中的建筑数量与镜头不变，缩小后直接使用缓存；返回校园没有新增底图请求。关闭 HTTP 缓存后刷新，仍由 Cache Storage 命中分块，只请求目录。
- 自动测试覆盖多种桌面和手机初始范围的完整性、哈希一致性、请求去重、跨页面缓存、版本隔离、损坏缓存及失败重试、前台优先和并发上限。
- 浏览器另行模拟外围返回 503：校园与七个入口继续显示、后台不提前启动，重试后镜头不变；按住地图拖动期间没有发起新预取请求。390×844 手机视窗检查通过，无横向溢出。

入口代码：`src/lib/use-campus-data.ts` 管理分阶段加载，`src/lib/basemap-loading.ts` 管理请求与解析，`src/lib/basemap-cache.ts` 管理持久缓存，`scripts/osm/build-runtime.mjs` 生成运行时分块。
