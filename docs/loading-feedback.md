# 加载反馈与校园建筑首屏

三处加载提示共用 `LoadingProgress`，只包含文字、一条 CSS 进度线和透明度动画；没有动画图片、第三方依赖、逐帧 React 更新或持续计时器。系统选择“减少动态效果”时停用动画。

## 进度与缓存

- **校园地图**：目录就绪 → 校园核心几何就绪 → 当前昼夜的七张建筑图解码 → 画面提交。制图阶段在两句文言文中随机选一句，一轮加载内保持不变。周边地图不计入首屏等待。
- **模型**：模块准备 → 构建建筑与窗口 → 编译和首帧渲染。首帧提交后移除进度条；原有高清照片继续渐进补齐，不重新阻塞模型。
- **关于食光**：纸纹与墨迹并行下载、解码，就绪后展示信纸。当前页面会话中成功准备的资源会缓存；再次打开直接展示，关闭过程中仍在准备的资源也能复用。失败保留重试入口。

进度线表示准备阶段，不声称是下载字节百分比，也不预测剩余秒数。不设置最短动画时长；缓存快时可以直接跳过中间文案。

## 建筑只剩影子的原因与修复

原来的建筑 SVG 图片在底图挂载后才被浏览器发现，下载可能与周边地图竞争；图片尚未显示时，独立绘制的阴影已经可见。

生产 HTML 现在提前发现当前主题的七张 WebP（白天合计约 317 KB，夜晚约 387 KB），与核心底图并行请求。React 同样在校园页挂载时启动共用解码任务，兼容开发环境和从模型返回地图。两种入口使用一致的 URL 与请求模式，复用下载。直达模型页不预取这些校园图片。

建筑准备期间暂缓周边数据请求。图片没就绪或加载失败时保留可点击的简易立体轮廓，避免只剩影子。单张图片请求及解码最长等待 15 秒，失败后可手动重试，不会无限自动重试。昼夜切换和离开页面后的旧任务不会覆盖当前加载状态。

## 验证方式

- `npm test` 覆盖解码完成、缓存、失败与超时重试，以及 HTML 预加载的主题与路由隔离。
- `npm run build` 检查 TypeScript 和生产资源路径。
- 浏览器使用手机视口、CPU 限速和受控图片延迟，检查建筑轮廓、阶段文字和请求顺序；故意断开单张图片后检查手动恢复。
- 检查信件重复打开没有加载条、昼夜切换图片正确、模型加载中返回校园不会出现过期模型，以及减少动画设置。

手机视口与限速用于重复验证加载流程，不能替代真实手机的 GPU 和内存表现测试。
